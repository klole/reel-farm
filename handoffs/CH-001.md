## 2. User-visible result

At the implementation commit, the repository contains a real private manual studio path: an owner can initialize one local installation, sign in, create and rename projects, edit a persisted slideshow document, upload owned local JPEG/PNG/static-WebP images, choose among three layouts and two canvas formats, adjust manual text and image framing, autosave with immutable revisions, recover from a stale-tab conflict, request a durable render, inspect protected final JPEG preview bytes, and download the ordered ZIP when a live database and worker are available.

The exact clean-install path is:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm setup
docker compose up --build
```

The local URL is `http://localhost:3000/setup`. `pnpm setup` prints the one-time owner token and preserves it thereafter; no credential is included in this handoff. A host-development run instead needs a reachable PostgreSQL `DATABASE_URL`, then `pnpm db:migrate`, `pnpm dev:web`, and `pnpm dev:worker` in separate terminals. Compose persists PostgreSQL in `oss_db_data` and private media/artifacts in `oss_media_data`; `docker compose down` keeps them, while `down -v` deletes them.

The current host could not start that stack. The UI/worker paths are implemented, but the real database, browser, worker, and export journey was not claimed as exercised.

## 3. Scope and architecture

- `packages/contracts`: versioned `oss.slide/1` document schema, trusted layout/font/canvas catalogs, bounded text/box/image values, asset-reference validation, deterministic `oss.canonical/1` hashing, post formatting, and stable IDs through reflow.
- `packages/db` plus `migrations/0001_ch001.sql`: Better Auth tables and the CH-001 workspace/project/draft/revision/asset/render/outbox/artifact/heartbeat/save-mutation model with foreign keys and idempotency constraints.
- `packages/storage`: private absolute media root, safe generated keys, Sharp decoding/normalization, EXIF-stripping derivatives/thumbnails, byte/pixel/edge/frame limits, staging/promotion/cleanup, and hash-aware reads.
- `packages/renderer`: one React `SlideScene`/CSS implementation used by editor preview and the worker, with embedded Inter and Source Serif 4 font bytes and a recorded font-set hash.
- `packages/core`: document hashing, post text, and export manifest construction.
- `apps/web`: Next.js owner setup/login, CSRF/origin protection, owner/workspace scoping, projects and revision APIs, protected media/final-output routes, and the manual editor.
- `apps/worker`: separate pg-boss worker with a PostgreSQL outbox reconciler, leases/fencing, stale-request recovery, local-only browser routing, narrowed Chromium environment, required-font/image/overflow/hash diagnostics, bounded render timeout, exact JPEG capture, and ordered ZIP packaging.

Authentication is Better Auth 1.7.4 with database sessions, finite seven-day expiry, rate limiting, private bootstrap setup, and a PostgreSQL advisory setup lock to serialize the one-owner race. State-changing app/auth routes use a double-submit CSRF token plus same-origin/cross-site checks. Uploads are staged before accepted DB records and are never served from a public static directory.

The render intent and outbox row are inserted in one application transaction. The worker claims requests with leases and uses a final DB lease check/unique artifact row before marking a request ready. This is an outbox/reconciliation design rather than a direct cross-connection pg-boss transaction. The current `test:integration`, `test:e2e`, `test:render`, and `test:smoke` commands are honest environment guards; they are not presented as full live harnesses.

No existing application implementation was overwritten. The two unrelated untracked user files named above were preserved. No provider SDK, Pinterest, AI, social connection, publishing, scheduling, billing, MP4/video, public deployment, release, or v0.2.0 work was added.

## 7. Security and boundaries

- Compose publishes only `127.0.0.1:3000`; database and worker have no host ports. The worker runtime is non-root, has `no-new-privileges`, and drops all capabilities.
- Owner routes scope every project, asset, revision, render, image, and ZIP lookup to the authenticated singleton workspace. Public signup is blocked; setup requires the one-time bootstrap token and is serialized.
- Mutations require same-origin/origin checks plus the `oss_csrf` double-submit token. Sessions are database-backed and finite; Better Auth telemetry is disabled.
- Uploads are bounded at 20 MiB/file, 100 MiB/batch, 40M decoded pixels, 16,384-pixel edges, and one frame; filenames are display-only and storage keys reject traversal/separators.
- The renderer receives validated local data URLs and embedded fonts, blocks non-data navigation, has no `--no-sandbox` workaround, and launches with a deliberately narrow environment containing only safe browser process values. The worker validates derivative hashes again and fails missing/corrupt media explicitly.
- Runtime network and effective container/browser sandbox behavior were not observed because the local stack could not run. The static/security suite passed 4 tests, but it is not a replacement for live containment evidence.
